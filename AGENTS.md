# AGENTS.md — Инструкции для ИИ-агентов

Этот файл содержит контекст и рекомендации для ИИ-ассистентов, работающих с проектом **Парчис (Pachisi)**.

## О проекте

**Парчис** — настольная/board игра для 2–4 игроков, реализованная как веб-приложение. Игроки бросают кости, выводят фишки из базы, двигают их по общей дорожке против часовой стрелки и стремятся привести все фишки в свой «дом» (финиш).

Подробные правила игры описаны в [`README.md`](README.md).

## Архитектурные принципы

### Разделение ответственности

- **`src/lib/`** — чистая игровая логика (FP-стиль). Не должна содержать Vue-компоненты, reactive-ссылки или зависимости от фреймворка. Функции принимают данные и возвращают новые данные.
- **`src/stores/`** — Pinia stores, которые управляют реактивным состоянием приложения. Вызывают функции из `lib/` для вычислений.
- **`src/components/`** — Vue-компоненты, отвечающие только за отображение и пользовательский ввод. Должны быть максимально «глупыми» (presentational).

### Стиль кода

- **TypeScript strict mode** — все типы должны быть явно указаны, избегай `any`.
- **Composition API** — используй `<script setup lang="ts">` в Vue-компонентах.
- **Функциональный подход** — в `lib/` предпочитай чистые функции, иммутабельность, композицию.
- **Именование**:
  - Компоненты: `PascalCase.vue`
  - Файлы с логикой: `camelCase.ts`
  - Stores: `camelCase.ts` (с экспортом `useXxxStore`)
  - Переменные/функции: `camelCase`
  - Типы/интерфейсы: `PascalCase`

### Работа с состоянием

- Используй Pinia stores для глобального состояния (игра, доска, игроки).
- Локальное состояние компонентов — через `ref`/`reactive`.
- Избегай мутаций состояния напрямую — используй actions в stores.

### Игровая логика

- Вся логика правил игры (валидация ходов, определение победителя, расчёт бонусов) должна быть в `src/lib/`.
- Stores должны делегировать вычисления в `lib/`, а не содержать бизнес-логику.
- Используй иммутабельные обновления: возвращай новые объекты/массивы вместо мутации существующих.

## Ключевые сущности игры

### Игрок (`Player`)

- Цвет (красный, синий, зелёный, жёлтый)
- Набор фишек (4 шт.)
- Позиция на доске
- Бонусы (от сбивания и попадания в дом)

### Фишка (`Chip`)

- Принадлежность игроку
- Позиция (база, общая дорожка, цветная дорожка, дом)
- Статус (активна, сбита, в доме)

### Ячейка (`Cell`)

- Тип (стартовая, обычная, безопасная, вход на цветную дорожку, финиш)
- Позиция на доске
- occupants (фишки на ячейке)

### Доска (`Board`)

- 67 ячеек общей дорожки
- 4 базы (по углам)
- 4 цветные дорожки (по 8 ячеек)
- 4 дома (центральные зоны)

### Кости (`Dice`)

- Два кубика (1–6)
- Результат броска
- Доступные ходы

## Правила для ИИ-агентов

### При написании кода

1. **Сначала пойми контекст** — прочитай связанные файлы в `lib/` и `stores/` перед изменением.
2. **Соблюдай разделение ответственности** — не смешивай логику и отображение.
3. **Пиши типобезопасный код** — избегай `any`, используй интерфейсы для сложных структур.
4. **Комментируй сложную логику** — особенно в `lib/`, где реализованы правила игры.
5. **Тестируй изменения** — запускай `npm run type-check` и `npm run lint` перед коммитом.

### При рефакторинге

1. **Сохраняй обратную совместимость** — если меняешь API в `lib/`, обнови все вызовы в `stores/` и `components/`.
2. **Не нарушай FP-принципы** — в `lib/` только чистые функции.
3. **Документируй изменения** — обнови этот файл, если меняешь архитектуру.

### При добавлении новых фич

1. **Определи, где место фиче**:
   - Новая игровая механика → `src/lib/`
   - Новое реактивное состояние → `src/stores/`
   - Новый UI-элемент → `src/components/`
2. **Следуй существующим паттернам** — посмотри, как реализованы похожие фичи.
3. **Обнови типы** — если добавляешь новые сущности, создай интерфейсы в соответствующих файлах.

### При отладке

1. **Проверяй состояние stores** — используй Vue DevTools для инспекции Pinia.
2. **Трассируй игровую логику** — добавляй `console.log` в `lib/` для отладки вычислений.
3. **Сверяйся с правилами** — если поведение кажется странным, проверь [`README.md`](README.md) с правилами игры.
